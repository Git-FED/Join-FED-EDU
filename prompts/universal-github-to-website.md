# Universal GitHub-to-Website Prompt

## PROJECT INPUT
Turn the supplied GitHub project into a complete, premium, eye-catching static website while preserving the project's truthful purpose, links, license, and contribution rules.

## FIRST UNDERSTAND
Read the README, docs, license, issue templates, and deployment files. Identify the audience, primary action, content hierarchy, and any privacy or security boundaries.

## STANDALONE HTML REQUIREMENT
Create a self-contained static site with semantic HTML, local CSS/JS where practical, responsive layout, visible focus states, reduced motion, and graceful no-JavaScript behavior.

## CREATE THESE PAGES
Create a landing page, a clear getting-started path, support/contact page, FAQ, and a custom 404 page when the source project benefits from them.

## CROSS-PAGE NAVIGATION
Every page must have consistent navigation, a useful footer, working relative links, and a visible route back to the primary action.

## VISUAL DESIGN
Use a coherent design system, no arbitrary gradients, readable contrast, whitespace, restrained motion, and accessible typography.

## PAGE-SPECIFIC DIRECTION
Make the page-specific copy accurate to the project. For fed-edu, keep GitHub Organization Onboarding prominent in the title and hero.

## MOTION AND SCRIPT SAFETY
Respect `prefers-reduced-motion`, animate transform/opacity, avoid blocking the main thread, and make every interactive control keyboard usable.

## SUPPORT
Tell users where to report bugs, request features, ask onboarding questions, and report security concerns without exposing sensitive information.

## DELIVERABLES
Return complete files, an updated file tree, a link-check summary, and any assumptions that require maintainer review.

## REQUIRED QUALITY CHECK
Check internal links, headings, contrast, alt text, focus behavior, mobile layout, reduced motion, secret scanning, and license preservation.
